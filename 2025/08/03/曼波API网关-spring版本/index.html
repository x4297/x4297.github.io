Overview

体验了一下国内主流的spring（但是用的版本比较新），感觉许多概念和其他web框架挺像的，数据库用的地方不多，所以mybatis只是浅尝辄止，mybatisx和mybatisplus也试了下，java是挺啰嗦，但是配上idea的语法提示，感觉体验还不错。参考教程https://www.bilibili.com/video/BV14WtLeDEit，这一版没怎么讲xml配置，他们旧的教程以前也看过，有个古法xml配置开始的，看到后面头都晕了，也不会写，这个感觉比较适合入门。

Maven

忘了写开局配置了，只会maven，还不会gradle。新版idea（现在最新的是2025.1.x）默认使用maven-wrapper，网上查了下，大概意思是为了让不同人在同一个项目使用的maven版本相同，仿照gradle里面的，搞了一个wrapper。每次新建项目都会自动下载maven以及maven-wrapper，这样有个坏处是之前对maven的配置都失效了，主要是本地和远程maven仓库地址，本地默认c盘，感觉不太舒服，远程的默认在国外，网速不行。对每个项目修改maven及maven-wrapper配置。

IoC & DI

Inversion of Control (IoC) 控制反转，个人理解是将管理对象的职责（如创建对象、修改、删除），从应用程序（写代码的人）转移给容器（框架），由ioc容器创建并管理bean对象，在ioc容器里存放bean（组件、对象，暂时没了解到为什么叫bean）。Dependency injection (DI) 依赖注入，spring手册里面写di是ioc的一种特殊形式，个人理解就是声明组件依赖关系后，框架会把依赖自动注入进来，可以直接使用。

spring中声明/注册组件可以用下面几个注解，声明后spring会将对象自动加入ioc容器，需要用的时候可以从容器中获取。几个注解作用没有太大区别，名字不同是为了区分controller、service等不同层级。@RestController是@ResponseBody和@Controller的组合。

@Bean也可以声明组件，但一用来声明第三方库的组件。

@Autowired个人理解就是在声明依赖关系，比如我这个controller依赖一个service，声明完之后，spring会自动装配对应的bean，或者说自动把这个依赖注入进来。autowire常见的用法是标注在属性、setter、构造函数上，目前版本推荐在构造函数里面注入，写在字段上面比较简洁，但是在和构造函数混用时，有可能出bug。

获取bean时默认按类型，创建时默认是单实例，可以用@Scope修改，如果有多实例，可以用@Qualifier和@Primary指定具体要哪个。

AOP

Aspect Oriented Programming (AOP) 面向切面编程，和python中的装饰器有点类似，装饰器以前好像看到也属于aop。要导入AspectJ的包，直接maven里面导入aop的starter就行，不然要自己找对应版本。网上有说不需要的，但这个版本不导入的话，没有对应注解。这里是用aop实现了service方法的调用日志，通过dto实现参数返回值的记录。

在一个方法的前后增加部分功能，和装饰器/高阶函数很像，和interceptor不同的是，这个针对的是方法执行的流程，而不是http请求处理的过程。除了around，还有一个前置和两个后置的注解可以用，around比较全。spring aop的实现是基于动态代理的，这个和高阶函数感觉有点不同。

事务

因为本次没怎么用到数据库，其实不需要事务，为了演示也加上了。这里的事务和数据库里面的是一个意思，加@Transactional注解就行。事务里面有隔离级别isolation，这个和数据库里的是对应的，spring里面事务是针对方法的，可能存在嵌套的情况，一个使用了事务的方法调用另一个使用事务的方法，存在嵌套的情况，这时就有传播行为propagation的概念，是暂停上一个事务，还是使用同一个事务，还是不使用事务等。隔离级别具体的等数据库在抠。

参数绑定和校验

@RequestBody默认使用json接收数据，可以指定一个vo来接收，@Validated表明需要校验参数，vo里的字段为空默认不报错，要每个字段标注@NotNull、@NotEmpty，或者自定义校验。部分代码在controller里面。

@RequestParam可以指定参数名的映射，但是只能标在方法参数上面，标完后默认必须要传（不能为null），但可以改，不标的话可以为null。有很多个get参数时，想用vo来绑定参数，如果需要映射参数名，比如api-key转为apiKey，vo里面做不到，因为指定参数名的注解标不了，目前没找到可行的方法，只能不用vo了。

拦截器

类似其他框架的中间件，针对http请求处理的流程，可以在某个环节进行hook，和aop不同的是，可以获取http的请求和响应。

访问日志，通过vo记录请求参数和返回值，但是因为做了全局异常处理，没办法获取异常，看源码可以看到，如果使用了全局异常处理，ex直接为null。

简单的限速，通过@Value获取配置的值，@Order指定顺序。

拦截器需要在配置类中注册。大部分情况使用interceptor即可，servlet的filter比较少用。但是有种情况比较特殊，在interceptor中，请求体存放在stream中，读取一次就没了，不能读取，这个时候可以用filter把request替换成ContentCachingRequestWrapper，可以缓存请求体，不过要小心上传文件的场景，容易爆内存。

各种O的理解

教程里面还真就让去搜各种o的说明，也没说比较正式的叫法。用到了VO（Value/View Object），DTO（Data Transfer Object，还有个就叫TO的也差不多好像），DAO（Data Access Object，用了mybatis就叫Mapper了），POJO（Plain Old/Ordinary Java Object），PO（Persistent Object，感觉和Entity/model差不多）。还有几个没用过也不太了解的，BO（Business Object），DO（Data/Domain Object，类似PO或者Entity）。

vo用来前后端传数据，本次是请求和响应都用了vo。

dto用来controller和service互传数据，本次调用和返回都用dto进行传输。

dao的一种就是mapper，定义了直接访问数据库的方法。

po、do感觉就是实体类，定义了数据库中数据的结构。

pojo，随便写个简单的java类就是了，或者理解不是上面的就是pojo了。

理解可能还是有些不到位的地方。

Summary

spring和fastapi、django、flask、gin等框架，很多基础大家都有，思想是相同的，比如在http请求处理流程的某个阶段进行hook，spring提供了interceptor，有的提供了middleware，flask提供了hook函数。想要像写视图函数一样写spring，不分层也能写，按照规范分层写还挺累的，还有就是map多层嵌套，java应该没有python写的方便。

吐槽一下，drf提供了限速但spring没找到对应的，不过drf文档中说默认限速实现不是那么精确，猜测是因为默认情况有条件竞争，而且因为用到的场景比较简单，框架就没加锁解决，感觉做得好的话可以用redis实现。

不过除了spring framework（spring web mvc）、spring boot外，spring生态还包括了很多我暂时还没接触到的，看spring官网感觉spring生态圈还是比较庞大的。

spring不是第一次学，但之前学的懵懵懂懂的，这次不知道是因为教程简化了古法xml配置的介绍，还是因为自己根据一个比较明确而且不复杂的需求去动手，还是之前用其他框架写过小型的应用，感觉这次学得比较快，很多概念也是一下就理解了。

以前看过的ssm古法xml配置，狗看了都摇头，虽然现在不太记得了，记得一个是bean要写在xml里面，而不是标个注解，spring boot还是方便的。
