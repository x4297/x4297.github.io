Overview

上班的时候遇到过一种场景，有的设备要用短信认证，运维监控平台要接短信告警，但是支持的对接方式与现有短信平台完全不一致，或者是对设备部分功能进行二次开发，如包装ssl vpn设备账号查询、修改功能，增加某些自定义的限制以及认证、鉴权、日志、限速等功能。这个时候就需要在最终的client和server之间加一个中间层，进行数据格式转换和功能扩展。一开始也不知道这种行为算什么，有种中间商赚差价的感觉，后来看了《API安全技术与实战》，发现与里面描述的API网关有类似功能，算是一个功能较少的API网关。写的过程中也是遇到了一些问题，最终的代码也存在一些混乱的地方，于是想重构代码并删除内部信息，并记录下学习过程。本项目目的是作为一个模板，后续遇到类似需求可直接填充关键逻辑代码，减少基础功能重复开发，并尽可能覆盖到web框架更多的功能点，作为一个学习案例或者备忘录。

python学的多，所以用的python。短信接了2个，包装设备接口包了1个，最开始用的fastapi和sqlalchemy，但写完感觉写的不是很舒服，于是就想试试大名鼎鼎的django，restful api相关的扩展有django-rest-framework。用fastapi是有人推荐，用着挺方便性能也不错。用django而不用flask是因为，django包含了很多功能，这些功能flask一般也会用到，但flask要装一堆扩展，而扩展开发人员的水平参差不齐，相对隐患较大，以前好像见过某个cms因为启用某扩展从而引入了漏洞，个人倾向于选择基础功能比较齐全的框架。

接短信这件事，能理解存在众多短信网关，厂商不可能一一适配，但有的厂商实在做得太差了，这个后面再吐糟。

fastapi版本

主要用到的就几个库，fastapi、uvicorn、httpx、sqlalchemy、asyncpg和alembic，一个web框架，一个webserver，一个orm框架，一个配套的数据库迁移工具，httpx的api和requests十分相似，但是多了async的支持。首先创建虚拟环境。写到这的时候还刚好遇到了vscode python插件更新，导致自动切换虚拟环境失败，回退版本也不行，最后把vscode的session storage删了重来才恢复。虚拟环境目录我一般用.venv。

创建git仓库，python虚拟环境后，发现虚拟环境中的依赖也被记录到git仓库中了，这是我们不希望见到的，于是通过.gitignore进行排除。从上到下分别是虚拟环境、数据库迁移文件、python字节码缓存、ide项目配置（个人习惯排除）。

入口

程序的入口点，openapi_url=None是为了关闭自动生成的openapi文档，CommonConfig中存储了整个程序共同使用的配置。因为所有文件都放在cwd当前目录下，没有用包或者说模块来组织，所以导入没使用相对路径。

配置文件

后续迭代过程中，发现配置文件大致可分为两种，一种是不包含敏感信息的通用配置，无论是开发环境还是生产环境，无论部署方式如何，都不需要改动，比如django框架配置文件中的大部分，里面涵盖了app、middleware的导入顺序，时区，语言等。另一种是不同部署环境不同的，包含敏感信息的配置，如数据库连接信息，debug是否开启，甚至api key等。后一种的配置如果不配gitignore，容易把敏感信息传到git仓库中，导致信息泄露，但如果没有这部分配置，项目又跑不起来。以前看教程是用dotenv，把敏感配置写到.env文件中，然后导入到环境变量，但看起来实际上还是将配置写到文件中，和写到py文件后增加gitignore没有实质区别。为了灵活以及向后兼容，从settings中拆出了部分配置，放到了private_settings.py中（为了项目完整性，可增加该文件的模板文件，或者把示例放在settings中的注释）。

BaseConfig本来是想放在settings中，private里面再导入，可是会发生循环依赖报错，于是改了下，后续配置拆分还可以优化。

可以看到配置文件中有着认证（appid和secret，ip白名单），限速，上游接口参数等配置。

异步IO

在unix network programming中，有一章讲IO模型以及多路复用，当中提到的异步IO模型，在我看来算是最高效的一种，但书中也写了，在当时支持posix异步IO的操作系统比较罕见。目前看各个主流编程语言都有这方面的支持，个人对异步IO浅显的理解是，由用户程序告知自己什么时候该被挂起，由异步框架来调度什么时候该恢复运行，这样可以避免轮询或时间片轮转轮到自己时却还没准备好下一步，减少了上下文切换以及判断是否可继续运行的开销。python中简单得说，需要挂起等待时使用await，恢复时机由异步框架来调度。

fastapi可以支持异步IO，也可以用多线程/多进程的IO模型，sqlalchemy也支持异步的api，为了追求性能以及尝试新事物，最终决定用异步的写法。

上游接口对接

这边上游接口指的就是短信网关，先写这部分的逻辑。这块因为不同网关对接方式不一样，要根据实际情况重新边写具体逻辑，所以这边只是给出了一个简化的例子。上班时用到的需要先获取token，默认30分钟左右过期，这边简化掉了。成功时返回没什么见不得人的，就直接返回了，失败时为了捕获异常记录日志，做了统一处理，顺便屏蔽了具体报错。

视图函数

接下来先看一眼视图函数，规划是一个视图函数对应一个app。大致就是在发送短信的前后增加额外的功能，发送前先认证，检查发送频率是否达到限速，发送结束后/接口返回时记录访问日志及短信发送日志。依赖注入时根据官方文档描述，只要是callable的对象就可以（说实话这块的文档写得不是很清楚），为了不同app使用不同认证信息，这边重载了自定义类的__call__方法。最后延迟导入是以前见过flask里面有这么写的，刚好用上了。

依赖

fastapi绑定参数的方式叫做依赖注入，spring中也有类似概念，但具体是个什么意思，现在还没搞懂，感觉乱乱的。fastapi文档大致看了一遍，动手也动完了，但有些东西还是不懂，看或许能看懂，写起来可能还是要对着文档或者以前的代码。

当时学这块的时候，刚好在看一本讲c++函数式编程的书，感觉有些东西一下就通透了。函数式编程有个概念叫高阶函数，大致是说以函数作为另一个函数的输入或输出，这么一看其实和python中的装饰器非常类似，而装饰器可以看成一种语法糖，c/c++中并没有相同的概念，c++中实现高阶函数可以通过class初始化成员变量及重载()运算符实现。这么一看python的装饰器做的事情也不过如此，也是一样的道理。

同时，一个函数接受多个参数，固定其中某几个参数，从而形成新的函数，这个过程叫柯里化（currying），新的函数叫偏函数（partial）。很多语言都引入了函数式编程支持，比如filter、map、reduce、fold、range等等，python也不例外。仿照高阶函数的概念，我们根据不同app的配置，生成不同可调用对象，从而在依赖注入的过程中复用尽可能多的代码。

中间件

中间件有很多含义，比如nginx可以叫中间件，rabbitmq、kafka可以叫中间件，elasticsearch也可以，python web中的middleware，主要是指在视图函数前后进行处理的功能，可以类比成在进入视图函数前以及视图函数返回后进行hook。这里主要记录访问日志。type ignore是因为ide提示client可能为None，但其实我想不出来什么时候client能为None，总不能没有客户端信息吧。

限速

从两个维度进行限速，一是IP地址，二是手机号，通过查询访问日志及短信日志来判断单位时间内次数是否过多。要注意的一点是，限速与封禁或锁定发ip不同，限速是指让其单位时间内处理的请求不超过多少次，封禁若是封禁期间内再次触发，可考虑延长封禁时间。目前是直接在视图函数中调用来使之生效，后续可考虑放入中间件，也可参考drf的scope实现不同接口不同限速策略。

部署

这个部署做的比较简单，实际上只是用nohup放后台跑而已。nohup个人理解就是让进程屏蔽hang up信号，ssh连接断开时，虚拟终端的子进程会收到SIGHUP的信号，从而终止进程，nohup则可以让进程不中断。screen和tmux也可达到类似效果。

总结

因为是从生产环境（用的人不多，不算正经生产）改的，所以改完之后也懒得再测试了。

有人说fastapi只是将pydantic、starlette还有什么缝在了一起，而且宣传做的不错，名不副实，版本还没到1.0，不够成熟。个人还是保留意见，毕竟只是做了一个小小的web应用，使用程度不深。整体体验还是不错的，尤其是fastapi文档中强调了类型提示的作用，这几次做web应用的过程中，确实觉得有类型提示会舒服很多，特别是与原始的django和drf对比（这两个框架出来的时候，python还没有type hint，后续有单独的仓库stubs，为其提供类型提示pyi文件）。动态类型的语言缺陷体现了出来，搞得想换个语言来写。为了以后打go，除了csgo和mygo之外还有别的选择，后面还学了一手golang。

有几点小问题提一下，一个是fastapi的文档，基础的内容全看了一遍，高级的我也大致瞄了一下，写了很多，但感觉少了什么，而且感觉乱乱的（虽然django的文档我也觉得少了什么，尤其是django admin，很多都没写，搞得后面一直在debug框架），同作者的另一个框架sqlmodel文档不知道是还没怎么写还是，当时看的时候没什么内容，甚至在讲sql语句，无关的内容有点多，也没看到异步api怎么使用，本来是想选用sqlmodle而不是sqlalchemy的。另一个是依赖注入文档中只写常见用法，感觉很多细节没写到，依赖注入这块用多了感觉很乱，看着头晕。

某网络厂商的部分产品，文档是不全的，400是不懂的，嘴是很硬的。短信对接基本都要配置短信模板、参数等内容，但是文档没写手机号、短信的正文要用什么符号表示，打电话问400，他们接线的那人像是根本不懂http如何传参，问了半天解决不了，也不摇人，还说这个是短信网关的配置，甚至发了份别的公司的短信网关手册，公网ip也没脱敏。另一个产品问了半天问到个懂的，直接说参数名和编码方式是固定的，改不了，改的话算二开要钱。感觉很啥杯。
