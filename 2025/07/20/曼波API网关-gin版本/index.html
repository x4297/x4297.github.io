曼波API网关-gin版本

发表于2025-07-20|更新于2025-07-20|web开发
|浏览量:

Overview

体验了一下go以及web框架gin，体验到一半感觉有点像原始人，所以只是一个简单的demo，功能很多不完善。项目结构及部分通用代码参考Go Gin Boilerplate。

配置文件

这部分没什么东西，和参考的仓库基本一样，本来看到使用了第三方库viper，想砍掉这一块，但看了下viper的star有20k+，干脆直接留着了。大致就是从yaml文件中读取配置，为了简便，把读取不同环境配置的代码注释了，留着是因为用到了mergeconfig，做个示例。

模型

本次只是个demo，功能比较少，懒狗也懒得用数据库了（不想再学orm了），这里的模型主要是请求参数和日志。记得好像fastapi文档中有提到，为了区分数据库模型和http请求参数的模型，可以把数据库模型叫models，参数模型叫schema。这里为了简单就没区分了。

controller

mvc架构学的不是很好，个人理解controller和视图函数差不多一个意思。模拟了发送短信的接口，为了记录操作日志，将部分变量存入gin的上下文中供中间件使用。

middleware

这次用中间件实现了两个功能，一个是ip白名单，另一个是操作日志（输出到stdout）。

绑定路由及启动

因为只有一个接口，所以没有分组。

不同环境配置文件读取是后面才注释掉的（debug懒得加命令行参数），main函数里面usage懒得改了。

Summary

go和gin的文档看了几天，之前有看过go的语法，但是太久没用早忘了，回过来看go官网的教程示例，感觉还不错。至于gin的文档，感觉很乱，写了又好像没写，后面找项目结构示例刚好找到个可以参考的项目，于是直接照着写了，感觉gin有点类似flask，内容不多。

整体体验还行，尤其是语法提示，比如想输入config.SetConfigType，可以直接打后面的setconfig，也能跳提示，没有import的包也能给提示并自动import，python印象中不能这么提示。orm的话懒得学，没有用到就不评价了。

但感觉有些地方还是有点像原始人，比如参数字段校验，这次一点都没做，因为gin要写在结构体字段标签里面，也就是写在字符串里，没有一点提示，感觉下一个要转投spring的怀抱了。
